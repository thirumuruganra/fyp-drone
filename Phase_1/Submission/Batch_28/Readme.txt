=====================================================================
a. URL / SOURCE FOR DATASET
=====================================================================
No fixed dataset file is used. Real-region data is fetched live by the code and cached
locally (Implementation/cache, Simulation/regions). Synthetic graphs are generated from a
fixed random seed, so they are reproducible without any download.

  Buildings, restricted zones, water, land use
      OpenStreetMap via the Overpass API
      https://www.openstreetmap.org   (c) OpenStreetMap contributors, ODbL
      https://overpass-api.de/api     (mirrors are listed in Implementation/config.py)

  Terrain (digital elevation model)
      Copernicus GLO-30 DEM through OpenTopography Global DEM API
      https://portal.opentopography.org/API/globaldem   (free API key, optional)
      Fallback when no key is set: Open-Meteo elevation API (keyless)
      https://open-meteo.com/en/docs/elevation-api

  Weather (wind speed, direction, gust)
      Open-Meteo forecast API (keyless)
      https://open-meteo.com

  Study area
      Thiruvanmiyur, Chennai: 6 km box at 200 m lattice spacing (893 nodes,
      6,752 directed edges) for the planner; frozen 1.5 km region for the simulation.

  Synthetic scenarios
      S1 (50 nodes), S2 (~200 nodes), S3 (500 nodes), generated by
      Implementation/run_benchmarks.py with a fixed seed.

  Offline fallback
      Implementation/tests/fixtures/ holds small hand-made fixtures. They are NOT real data,
      only for tests and the --offline flag.

  SourceCode/Simulation/regions/ (thiru_demo and thiru_1500) holds the frozen OSM + DEM
  bundles used for the simulation, so the Gazebo world can be rebuilt without
  re-downloading. thiru_demo is the default region and the one used in the video;
  thiru_1500 is the former default (its depot is infeasible with live OSM data).


=====================================================================
b. SOFTWARE AND HARDWARE REQUIREMENTS
=====================================================================
HARDWARE
  Planner (Implementation/): any laptop or desktop CPU, 8 GB RAM or more recommended,
  no GPU needed. Tier 1 is a single-core graph search; Tier 2 is a closed-form
  computation (about 0.14 ms per pick).
  Simulation (Simulation/): a laptop-class machine that can run Gazebo Harmonic under
  WSL2 or native Linux, 16 GB RAM recommended, a working GPU driver for the Gazebo GUI.
  Phase II (planned, not part of this submission): F450 quadcopter, Pixhawk flight
  controller, Raspberry Pi 5 companion computer.

SOFTWARE - PLANNER
  Python 3 (developed and tested on Python 3.12, Windows 11)
  Packages (Implementation/requirements.txt): networkx, numpy, matplotlib, requests,
  shapely, geopandas, pyogrio, osmnx. Optional: rasterio (local GeoTIFF DEM).
  Tkinter (ships with Python) for dashboard.py.
  Internet access for live OSM / DEM / weather (not needed with --offline).

SOFTWARE - SIMULATION (Simulation/requirements-simulation.txt)
  Everything above plus: trimesh, mapbox_earcut, scipy, jinja2, pymavlink
  Ubuntu 24.04 (WSL2 or native)
  Gazebo Harmonic (gz-sim 8)
  ArduPilot SITL (ArduCopter) with sim_vehicle.py / MAVProxy
  ardupilot_gazebo plugin
  python3-gz-transport13, python3-gz-msgs10 (Debian packages, for the recording camera)
  QGroundControl (optional, for viewing and uploading the mission; on WSL2 the launcher
  opens the Windows install)

SOFTWARE - REPORT / POSTER
  LaTeX distribution (MiKTeX or TeX Live) with pdflatex; references are inline, so
  bibtex is not needed. Microsoft PowerPoint for the poster.

API KEYS (optional)
  OPENTOPO_API_KEY for the 30 m Copernicus DEM. Copy SourceCode/.env.example to
  SourceCode/.env and fill it in. Without a key the 90 m Open-Meteo DEM is used.


=====================================================================
c. HOW TO EXECUTE THE SOURCE CODE
=====================================================================
The code is shared only through this OneDrive folder (Batch_28); there is no Git
repository. Download Batch_28, extract it outside OneDrive, and run the commands below
from the extracted Batch_28 folder. Keep the folder layout (SourceCode/Implementation and
SourceCode/Simulation side by side). Simulation imports the planner from ../Implementation.

--- 1. Planner (Windows / Linux / macOS) ---------------------------
  cd SourceCode/Implementation
  pip install -r requirements.txt

  Windows only: set PYTHONUTF8=1 first (PowerShell:  $env:PYTHONUTF8 = "1").

  Synthetic airspace demo (no network):
      python run_demo_syn.py

  Real-region lattice demo (live OSM + DEM + weather, needs network):
      python run_demo_osm.py

  Fast offline run with fixtures and a chosen payload (F W U P):
      python run_demo_osm.py --offline --box-km 2 --payload 3 2 2 3

  Useful options of run_demo_osm.py:
      --preset NAME   --wind-override SPEED DIR_FROM   --refresh   --box-km N

  Benchmarks (Tier 1 vs A* and MOPSO, scenarios S1/S2/S3):
      python run_benchmarks.py --smoke                (quick check)
      python run_benchmarks.py --scenario S2           (S1, S2 or S3)
  Ablation of the risk layers:
      python run_ablation.py
  Operator dashboard (enter payload tags, view route, export mission; run
  run_demo_syn.py once first so it has a stored graph and front to load):
      python dashboard.py

  Payload tags: F fragility 1-5, W payload weight class 1-3, U urgency 1-3,
  P priority 1-5.

  Results are written to Implementation/outputs/ (figures, CSV, JSON, .waypoints).

  Unit tests (offline, 224 tests):
      python -m unittest discover -s tests

--- 2. Simulation (Gazebo + ArduPilot SITL, Ubuntu 24.04 / WSL2) ----
  One-time setup of Gazebo Harmonic, ArduPilot SITL and the ardupilot_gazebo plugin:
  follow "One-time setup" in SourceCode/Simulation/README.md.

  Copy the extracted Batch_28 folder into the Linux filesystem first (running from
  /mnt/c is much slower):
      cp -r /mnt/c/<path to>/Batch_28 ~/Batch_28
      cd ~/Batch_28/SourceCode/Simulation
      python3 -m venv ~/venvs/fyp && . ~/venvs/fyp/bin/activate
      pip install -r requirements-simulation.txt

  Plan (no Gazebo needed), using the frozen thiru_demo bundle shipped in regions/:
      python run_sim_mission.py --all-presets

  One command (world -> plan -> Gazebo + SITL -> fly -> evaluate), default region thiru_demo:
      source gazebo/env.sh
      python launch_simulation.py
      python launch_simulation.py --preset fragile_medical
      python launch_simulation.py --wait-for-start   (recording: holds on the pad until Enter)
  Under WSL2, telemetry goes to the Windows host and Windows QGroundControl is opened
  automatically (--no-ground-station to skip). If the Gazebo window stays blank, set
  GZ_IP=127.0.0.1 and GZ_RELAY=127.0.0.1 in ~/.bashrc.

  Manual alternative (three terminals):
      python gazebo_world_builder.py thiru_demo
      python run_sim_mission.py --preset fragile_medical
      bash gazebo/launch_region.sh thiru_demo missions/<run_id>
      sim_vehicle.py -v ArduCopter -f gazebo-iris --model JSON --map --console -w ...
          (exact command in worlds/thiru_demo/sitl_command.txt)
      python sitl_mission_runner.py missions/<run_id>
      python evaluate_gazebo_run.py runs/<run_id>__<time>

  To rebuild the bundle from live data (needs network):
      python prepare_sim_region.py --strict

  Unit tests (needs trimesh):
      python -m unittest discover -s tests

  If bash reports "$'\r': command not found" (a script was saved on Windows):
      sed -i 's/\r$//' gazebo/*.sh gazebo/*.parm

  Full step-by-step, frame conventions and WSL notes: SourceCode/Simulation/README.md.
  Planner details (files, options, known limits): SourceCode/Implementation/README.md.

--- 3. Report (LaTeX) -------------------------------------------------
  Unzip Report/Batch_28_Report.zip, then in the extracted folder:
      latexmk -pdf ug-project-report.tex
  (or run pdflatex twice). The compiled ug-project-report.pdf is already included.

--- Notes ----------------------------------------------------------------
  * Battery constants and the weather no-go gust limit in Implementation/config.py are
    placeholders, not calibrated values.
  * Gazebo wind is not simulated; the SITL run validates the route, upload, flight and
    landing, not wind response.
  * Simulated outputs are labelled as such in the report, poster and video.
